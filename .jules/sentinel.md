## 2024-06-14 - DOM XSS in Static Landing Page
**Vulnerability:** DOM-based Cross-Site Scripting (XSS) via unescaped user inputs injected into `innerHTML`.
**Learning:** The static landing page (`docs/index.html`) relies entirely on client-side JS to render the UI dynamically based on form inputs and `localStorage` states. Even though there's no server-side persistence or query-parameter reflection, user-provided inputs like birth star profile names or dates were being concatenated into template literals and directly assigned to `innerHTML` (e.g., in Muhurta and Gochara tabs). The codebase had an existing `muEsc` function but failed to use it universally for these inputs, allowing for Self-XSS. While the attack vector is localized, it violates the "trust nothing" principle and defense-in-depth architecture.
**Prevention:** Renamed the specific `muEsc` function to a generic `htmlEsc` and rigorously wrapped all user-controlled template literals injected into the DOM. Ensure that all future client-side DOM manipulations explicitly sanitize inputs.
