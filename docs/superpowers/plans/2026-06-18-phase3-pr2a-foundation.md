```python
#!/usr/bin/env python3
"""Codegen ACTIVITY_RULES -> src/data/activity-rules.generated.json.

READ-ONLY consumer of the frozen scorer. Runs in CI via the pytest drift
test; `--check` exits nonzero if the committed file is stale.
"""
import json
import pathlib
import sys

from telugu_panchangam.personal.muhurta import ACTIVITY_RULES

OUT = pathlib.Path(__file__).resolve().parent.parent / 'src' / 'data' / 'activity-rules.generated.json'


def _normalise(value):
    if isinstance(value, (tuple, set)):
        return [_normalise(v) for v in value]
    if isinstance(value, list):
        return [_normalise(v) for v in value]
    if isinstance(value, dict):
        return {k: _normalise(v) for k, v in value.items()}
    return value


def build_payload() -> str:
    payload = {
        'generated_by': 'tools/export_activity_rules.py',
        'source': 'telugu_panchangam.personal.muhurta.ACTIVITY_RULES',
        'activities': {k: _normalise(v) for k, v in ACTIVITY_RULES.items()},
    }
    return json.dumps(payload, indent=2, sort_keys=True) + '\n'


def main(argv: list[str]) -> int:
    after = build_payload()
    check = '--check' in argv
    before = OUT.read_text(encoding='utf-8') if OUT.exists() else ''
    if check:
        if before != after:
            print(
                'activity-rules.generated.json is stale; '
                're-run without --check.',
                file=sys.stderr,
            )
            return 1
        return 0
    OUT.parent.mkdir(parents=True, exist_ok=True)
    OUT.write_text(after, encoding='utf-8')
    return 0


if __name__ == '__main__':
    raise SystemExit(main(sys.argv[1:]))
```

### Task 3: Parity fixture codegen (scorer inputs + expected outputs)

This is the load-bearing contract artifact and a **most-capable-model** task. It builds real `PanchangamDay` objects via the engines, runs `day_slots()`, and serializes BOTH (a) every fact the scorer reads — the `scorer_day` object — AND (b) the exact slot output, over a matrix that exercises every 1.9.0 differentiator. PR 2b's TS scorer takes a `scorer_day` and must reproduce the slots.

**Spec source of truth (read these before writing):** `telugu_panchangam/personal/muhurta.py:794–1194` (`_evaluate_slot`, `day_slots`), `:83–101` (`assign_tiers`), and `telugu_panchangam/mcp/tools.py:922–1021` (`_gather_muhurta_slots` / `tool_find_muhurta`) for the cross-day re-tier + `slots[:12]` seam.

**Files:**
- Create: `tools/export_parity_fixture.py`
- Create: `src/data/parity-fixture.generated.json` (written by the script)
- Create: `tests/test_parity_fixture_export.py`

**Interfaces:**
- Consumes (READ-ONLY):
  - `engine.calculate(d: date, location: Location, include_eclipse: bool = True) -> PanchangamDay` via the cached singletons in `telugu_panchangam/mcp/tools.py` (`_get_engine(system, ayanamsa='lahiri')`, systems `drik`/`surya_siddhanta`/`vakya`).
  - `telugu_panchangam.personal.muhurta.day_slots(day, activity, janma_nakshatras, janma_rasis, janma_lagnas, chandra_mode, travel_direction, *, engine=None) -> list[dict]`.
  - `Location(name, lat, lon, timezone, alt=0.0)` from `telugu_panchangam/models/panchangam_day.py`.
  - City coordinates: reuse the existing city table the MCP tools use (find how `tool_find_muhurta` resolves `city` → `Location`; do not hand-type coordinates).
- Produces: `src/data/parity-fixture.generated.json`, a list of `case` objects (schema below). PR 2b's TS parity test and `types.ts` consume it.

**`scorer_day` serialization rule:** the `scorer_day` object MUST contain every `PanchangamDay` attribute the scorer reads, JSON-serialized (datetimes as ISO-8601 strings, `Span`/`Window` as `{name?, start, end}`, `MaudhyaInfo` as `{graha, elongation_deg, combust, threshold_deg}`, `PanchakaInfo` serialized to the fields `day_slots` reads). At minimum, from the verified field list: `date`, `vaaram`, `tithi`, `nakshatra`, `yoga`, `karana`, `paksham`, `maasam`, `sunrise`, `sunset`, `choghadiya`, `abhijit_muhurta`, `amrita_kalam`, `is_amavasya`, `eclipse`, `anandadi_yoga`, `simha_stha_guru`, `simha_stha_shukra`, `guru_maudhya`, `shukra_maudhya`, `sankramana_avoidance`, `is_khar_maasa`, `is_pitru_paksha`, `in_panchaka_nakshatra`, `panchaka_rahita`, `bhadra_puchha`, `nakshatra_mukha`, `disha_shoola_direction`. **Determine the complete set by reading `_evaluate_slot`/`day_slots`** — if the scorer reads a field, it must be in `scorer_day`. Also serialize any windows `day_slots` computes internally and feeds to `_evaluate_slot` (the per-slot time `block`s, the `horas` list, the `lagnas` transition list) — capture them as the script observes them, so the TS side scores identical inputs rather than re-deriving ascendants.

**Matrix (exercise every differentiator, §E of the refreshed plan):**
- Base score-stacking activities: `travel`, `wedding`, `vehicle`, `gruhapravesha`.
- `cremation` (or `construction_roof`) — `skip_on_panchaka_nakshatra`.
- `litigation` — `prefer_bhadra_puchha`.
- `well_digging` (or `coronation`) — `prefer_nakshatra_mukha`.
- At least one samskara (`wedding`/`upanayana`) on a hand-picked **sankramana / khar-maasa / adhika / pitru-paksha / simha-stha-guru / combust** day → expected `slots == []` and a `dropped_day` reason.
- Hand-picked date+profile forcing `day_dosha == 'amavasya'` and one forcing `personal_dosha == 'ashtama_lagna'` (neither is guaranteed by random dates).
- Profile dimension: `{none}`, `{janma_nakshatras:[…]}`, and `{janma_nakshatras, janma_rasis, janma_lagnas}` (the last exercises the dual-lens Lagna Shuddhi audit trail).
- Cities/systems: ≥3 cities × the 3 systems across the chosen dates (need not be a full cross-product; cover each system at least twice).
- Pick dates deterministically from a fixed list literal in the script (NOT today's date) so the fixture is reproducible.

**`case` schema (each element of the JSON top-level `cases` list):**
```
{
  "id": str,                 # stable, e.g. "wedding_hyderabad_drik_2027-02-14_p1"
  "city": str, "system": str, "date": str,
  "activity": str,
  "profile": {               # the day_slots kwargs for this case
    "janma_nakshatras": list|null,
    "janma_rasis": list|null,
    "janma_lagnas": list|null,
    "chandra_mode": str,
    "travel_direction": str|null
  },
  "scorer_day": { ... },     # serialized facts (see rule above)
  "expected_slots": [        # output of day_slots(), datetimes as ISO strings
    {"date","vaaram","start","end","score","personal_dosha","day_dosha","reasons","reason_groups","tier"}
  ]
}
```
A separate top-level key `find_muhurta_cases` (≥2 cases) captures the whole-search seam: run `tool_find_muhurta(...)`, store its parsed JSON (`slots[:12]` + `dropped_days`) as `expected`, so PR 2b can verify cross-day re-tiering + truncation, not just per-day `day_slots`.

> Resolves refreshed-plan Open Decision 4: the fixture captures BOTH seams — `expected_slots` at the `day_slots()` (per-day) seam that `evaluateSlot`/`daySlots` port, and `find_muhurta_cases` at the `tool_find_muhurta()` whole-search seam.

import { describe, it, expect } from 'vitest';
import activityRules from '../../data/activity-rules.generated.json';
import parityFixture from '../../data/parity-fixture.generated.json';
import type { ActivityKey, ActivityRule, ParityCase, Tier } from '../types';

const ACTIVITY_KEYS: ActivityKey[] = [
  'any','travel','wedding','vehicle','gruhapravesha','engagement','naming',
  'annaprasana','mundana','karnavedha','upanayana','vidyarambha','gold',
  'property','purchase','business','job','ceremony','beginning','bhumi_puja',
  'yajna','pilgrimage','court','litigation','surgery','cremation',
  'construction_roof','wood_cutting','well_digging','coronation',
];
const ALLOWED_RULE_KEYS = new Set<keyof ActivityRule>([
  'label','skip_on_yoga','prefer_choghadiya','avoid_karana','prefer_tithi_class',
  'prefer_vara','prefer_lagna_class','skip_on_sankramana','skip_on_khar_maasa',
  'skip_on_adhika','skip_on_pitru_paksha','skip_on_simha_stha_guru',
  'penalty_on_simha_stha_shukra','skip_on_combust','prefer_nakshatra_mukha',
  'skip_on_panchaka_nakshatra','prefer_bhadra_puchha',
]);
const TIERS = new Set<Tier>(['Avoid','Fair','Good','Excellent']);

describe('activity-rules.generated.json conforms to types', () => {
  const activities = (activityRules as any).activities as Record<string, any>;

  it('every generated key is a known ActivityKey', () => {
    expect(new Set(Object.keys(activities))).toEqual(new Set(ACTIVITY_KEYS));
  });

  it('every rule field is an allowed ActivityRule key', () => {
    for (const [key, rule] of Object.entries(activities)) {
      for (const field of Object.keys(rule)) {
        expect(ALLOWED_RULE_KEYS.has(field as keyof ActivityRule), `${key}.${field}`).toBe(true);
      }
      expect(typeof rule.label).toBe('string');
    }
  });
});

describe('parity-fixture.generated.json conforms to types', () => {
  const cases = (parityFixture as any).cases as ParityCase[];

  it('has cases', () => { expect(cases.length).toBeGreaterThan(0); });

  it('every case activity is a known ActivityKey', () => {
    for (const c of cases) {
      expect(ACTIVITY_KEYS.includes(c.activity), c.activity).toBe(true);
    }
  });

  it('every expected slot has a valid tier and serialized datetimes', () => {
    for (const c of cases) {
      for (const s of c.expected_slots) {
        expect(TIERS.has(s.tier), `${c.id}:${s.tier}`).toBe(true);
        expect(typeof s.start).toBe('string');
        expect(typeof s.end).toBe('string');
      }
    }
  });
});
